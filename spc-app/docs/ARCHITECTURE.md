# SPC 均值–极差图系统 · 架构说明

## 1. 总览

浏览器里运行的统计过程控制（SPC）工具。一台机床的一个尺寸 = 一个**监控对象**，
独立建档、独立切组、独立冻结控制限与判异。

- 后端：Go 1.22 + Echo + PostgreSQL 16（pgx 连接池）
- 前端：Vue 3 + Vite，纯 SVG 自绘控制图，无第三方图表库
- 部署：docker-compose 三容器（backend / nginx 前端 / postgres），浏览器只访问 nginx

职责分层（后端）：

| 包 | 职责 |
|---|---|
| `internal/spc` | 标准常数表、切组、中心线/控制限、组内 σ、Cp/Cpk（**全部数字只在这里算**） |
| `internal/rules` | 四条 Nelson 判异规则的纯函数引擎 |
| `internal/model` | 持久化/接口共享结构 |
| `internal/repo` | pgx 数据访问，不含业务判断 |
| `internal/service` | 校验、切组编排、冻结/重基准、判异重放与落库 |
| `internal/api` | Echo 路由、请求绑定、字段级错误响应 |
| `internal/db` | 连接池、等待就绪、嵌入式 SQL 迁移 |

前端不计算任何控制限或能力指数，只渲染后端返回的数字。

## 2. 子组与切组（多检验员并发）

- 每个测量值在 `measurements` 表中有档案内全局连续序号 `seq`（从 1 开始）。
- 录入请求在一个数据库事务里先对档案取 **pg 事务级咨询锁**
  `pg_advisory_xact_lock(target_id)`，再 `count(*)` 取起点，随后把整批值
  `unnest` 批量插入并连续占用 `seq = count+1 … count+k`。
- `(target_id, seq)` 有唯一索引兜底。
  - 同档并发：咨询锁串行化，两批各自连续占段 → **不丢不重**。
  - 一次粘贴的整列数在同一次插入中连续入序 → 顺序即服务器收序。
  - 不同档案：咨询锁 key 不同，互不阻塞。
- 子组 = `seq` 顺序按档案子组容量 `n` 切分：第 1..n 个是第 1 组，以此类推。
  末尾不足 n 个为残段，回传给前端提示，不参与任何统计。
- 录入后端只接受「单值」或「总数恰为 n 整数倍」的批量；多值但不对齐直接报错，
  避免静默产生残段。单值可逐个补齐残段。

## 3. 两阶段控制限（冻结 / 重新基准）

- 基准期 = 指定的一段连续完整子组（`basisStart..basisEnd`，**至少 20 个**，少于 20 拒绝冻结）。
  发起时可给 `basisStart/basisEnd`，缺省取当前全部完整子组。
- 冻结时计算并存档：
  - Xbar 图：`Xbarbar ± A2·Rbar`
  - R 图：`D4·Rbar`、`D3·Rbar`
  - 组内标准差：`σ = Rbar / d2`
  - 能力：`Cp=(USL-LSL)/6σ`，`Cpk=min((USL-Xbarbar)/3σ,(Xbarbar-LSL)/3σ)`
- 冻结后新录入的子组**只按冻结限判定，不回算**限值。
- 「基准期范围」与「判定生效区间」是两个独立概念，分别落库：
  - `basis_start/basis_end`：限值/能力是用哪些子组算出来的（溯源用）；
  - `start_group/end_group`：该限对哪些子组生效（判定与显示用）。
- 「重新基准」必须显式发起：
  - 旧基准 `active=false`，`end_group = 冻结时总组数`，旧限与其生效区间留档；
    即重新基准那一刻**之前**的全部历史点（含基准期）永远按旧限显示与判异；
  - 新基准 `start_group = 冻结时总组数+1`，只判定之后新录入的点；
  - 旧基准的告警挂在旧 `baseline_id` 下永久留档（不删除）；新基准在其生效区间内
    （此刻还没有点）重放，后续追加时增量对齐。
- 图上每个子组点带 `baselineId/version`；某点归属 = `start_group ≤ 点序号 ≤ end_group`
  （`end_group` 为空表示至今）。前端按段画该段当时的限，
  所以**历史点永远按当时生效的限显示**，旧限与新限在图上是不同颜色的线段。

## 4. 判异规则（四条 Nelson，仅判均值图）

| 编号 | 规则 | 窗口 | 登记时机 |
|---|---|---|---|
| R1 | 一点超出 3σ（严格 `>UCL` 或 `<LCL`，恰在限上不算） | 1 | 该点 |
| R2 | 连续 9 点在中心线同侧（中心线上的点打断） | 9 | 第 9 点 |
| R3 | 连续 6 点严格递增或严格递减（相等打断） | 6 | 第 6 点 |
| R4 | 连续 3 点中 ≥2 点在同侧 2σ～3σ 区（2σ 边界计入，超 3σ 点也计入） | 3 | 第 3 点 |

每条规则可独立开关；告警记录规则编号、窗口首末子组、涉及的全部子组序号与中文说明。

### 4.1 评估策略：整段从头重放（reconcile），而非增量维护窗口

**选择的方案**：每次需要更新告警时（追加子组、重新基准、或切换判异开关），
在录入/基准的**同一个事务**内，对「该基准序列」从其起点开始跑一遍纯函数
`rules.Evaluate`，再把结果与 `alarms` 表对齐——新告警插入、已不存在的删除
（表上有 `(baseline_id, rule, first_index, idx)` 唯一键保证幂等）。

**为什么不用增量窗口状态机**：

1. **一致性可证**。规则全部按「窗口末点」登记：一个长度为 k 的规则最早只能在
   第 k 点成立，之后追加新点不会改变前 k 点的事实。因此
   - 在线逐点追加累积出的告警集合 ≡ 对最终序列整段重放的告警集合；
   - 按时间追加时，已出现的告警不会因为后来的点而消失（重新基准除外）。
   这条性质有单测 `TestOnlineAppendEqualsFullReplay` 守护。
2. **切换规则开关 / 重新基准天然正确**。增量状态机在规则开关变化或换限后，
   需要为每条规则维护并回滚各种计数器（同侧长度、趋势长度、2σ 区计数），
   极易出边界 bug；重放让「当前配置 + 冻结限 + 全序列」成为唯一事实来源。
3. 纯函数引擎无状态、易测试：每条规则的「恰好触发 / 差一点」都能直接构造序列断言。

**代价**：

- 每次追加重算 O(N)（N 为该基准下子组数）。车间每 2 小时一组，一条线一年约
  千组量级，O(千) 的内存循环 + 一次批量 upsert 完全可接受；真正的写库只发生
  在「新增告警」时，未变化的告警命中 `ON CONFLICT DO NOTHING`。
- 当单子组数达到数万、且高频录入时，可优化为「只重放最近 9 点窗口 + 持久化
  滚动状态」，但那会重新引入状态机一致性成本，当前规模不采用。

### 4.2 重新基准是唯一让旧告警消失的途径

规则关闭会删除**当前 active 基准**下该规则的告警（因为它表达的是“按当前启用
规则判定”），但**旧版本基准的告警不动**；重新基准后，旧告警挂在旧 `baseline_id`
下永久留档。这满足“重新基准除外”的一致性要求。

## 5. 过程能力

- Cp/Cpk 只在冻结基准时按**基准期**计算并落库，后续加数据不回算。
- σ 用组内估计 `Rbar/d2`。
- 单侧规格：只有 Cpk，Cp 返回 `null`。
- σ=0（基准期零极差）时比值无定义，Cp/Cpk 返回 `null`。
- 当前基准存在任意告警时，基准记录附 `note = "过程不受控，指数仅供参考"`；
  指数本身照常给出。

## 6. 输入校验（前端 + 后端同一套明确提示）

| 情形 | 字段 | 提示 |
|---|---|---|
| 测量值不是数 | `values` | 「第 n 个测量值不是数字: x」（粘贴逐个定位） |
| 批量数量与子组容量不符 | `values` | 「一次录入 k 个值不是子组容量 n 的整数倍…」 |
| 上限不大于下限 | `usl` | 「规格上限必须大于规格下限」 |
| 上下限都空 | `usl` | 「规格上下限至少填写一个」 |
| 子组容量不在 2–10 | `subgroupSize` | 「子组容量必须是 2 到 10 的整数」 |
| 基准期少于 20 组 | `basisEnd` | 「基准期至少需要 20 个子组」 |
| 基准范围越界 | `basisStart` | 「基准子组范围无效，当前共有完整子组 N 个」 |
| 建档后改子组容量 | `subgroupSize` | 拒绝（历史切组会失效，需新建档） |

后端返回 400 且 body 为 `{ error, fields:[{field,message}], message }`，
前端 Vite/表单做同样的即时提示（但以前端不算限、后端为最终准绳）。

## 7. 测试

`go test ./...`：

- `internal/spc`：居中 Cpk=Cp；规格宽度加倍 Cp 加倍；均值平移 Cp 不变 Cpk 降；
  单侧规格；规格校验；切组残段；零极差控制限退化。
- `internal/rules`：每条规则的恰好触发与差一点（8 点同侧、5 点趋势、
  恰在 3σ 线上、3 点中仅 1 点在 2σ 区、异侧不合、相等打断趋势等）；
  开关关闭不评估；**在线逐点追加 == 整段重放**。
- `internal/service`：批量数量与子组容量不符、基准范围、规格校验、非数字逐个定位。

需要 PostgreSQL 的集成测试用构建标签隔离，`go test ./...` 默认不跑：

```bash
SPC_TEST_DATABASE_URL=postgres://spc:spc@localhost:5432/spc?sslmode=disable \
  go test -tags=integration ./internal/service/ -run Integration -v
```

覆盖 8 个检验员并发录入 80 组不丢不重、冻结后限值不回算、重新基准旧限留档与
新点只按新限判定、在线告警与纯函数重放键集合一致。

## 8. 本地运行

```bash
docker compose up --build
# 浏览器打开 http://localhost:8088
```

本地开发：后端 `DATABASE_URL=... go run ./cmd/server`；前端 `npm install && npm run dev`
（Vite 已配 `/api` 代理到 :8080）。
